2. PROBLEMA ORIGINAL
================================================================================

SITUACIÓN REPORTADA:
-------------------
Usuario borra todos los datos de las tablas public.* (profiles, cases, etc.)
Cierra sesión
Intenta registrar el mismo email
❌ ERROR: "An account with this email already exists"
Pero las tablas están vacías

CAUSA RAÍZ:
-----------
El usuario está en auth.users (Supabase Auth), NO en public.profiles

FLUJO DEL PROBLEMA:
------------------
1. Usuario registrado → Crea entrada en auth.users
2. También crea entrada en public.profiles (FK → auth.users)
3. Usuario borra public.profiles manualmente
4. auth.users permanece intacto
5. Al intentar nuevo registro → Supabase valida contra auth.users
6. Encuentra el email → Rechaza el registro

ARQUITECTURA DUPLICADA ENCONTRADA:
----------------------------------
Sistema Activo:
  - auth.users (Supabase Auth)
  - public.profiles (vinculada a auth.users)

Sistema Legacy (NO USADO):
  - public.User (NextAuth)
  - public.Profile (NextAuth)
  - public.Account (NextAuth OAuth)
  - public.Session (NextAuth sessions)
  - public.VerificationToken (NextAuth tokens)

IMPACTO:
--------
- Confusión en el código
- Dos modelos Profile diferentes
- Mantenimiento complejo
- Bug de persistencia de usuarios

4.2. SERVER ACTION - devActions.ts
----------------------------------
Ubicación: src/app/actions/devActions.ts

Propósito:
  Proveer funciones de desarrollo para operaciones destructivas

Funciones implementadas:

  a) deleteUserCompletely(userId: string): Promise<ActionResponse>
  
     Descripción:
       Elimina completamente un usuario del sistema incluyendo
       todas sus relaciones por CASCADE
     
     Parámetros:
       - userId: UUID del usuario a eliminar
     
     Retorno:
       {
         success: boolean,
         message: string
       }
     
     Proceso:
       1. Valida NODE_ENV === 'development'
       2. Valida credentials de Supabase
       3. Valida formato de UUID
       4. Crea cliente admin de Supabase
       5. Ejecuta supabaseAdmin.auth.admin.deleteUser(userId)
       6. El CASCADE automático elimina:
          - public.profiles (FK: id → auth.users.id)
          - public.org_members (FK: user_id → auth.users.id)
          - auth.identities
          - auth.sessions
          - auth.mfa_factors
       7. Revalida rutas de Next.js
       8. Retorna resultado
     
     Seguridad:
       - Solo ejecuta en development
       - Requiere SUPABASE_SERVICE_ROLE_KEY
       - Valida UUID para prevenir SQL injection
       - Logging completo de operaciones
       - Manejo robusto de errores
  
  b) userExists(userId: string): Promise<boolean>
  
     Descripción:
       Verifica si un usuario existe en el sistema
     
     Uso:
       Función auxiliar para validaciones

Variables de entorno requeridas:
  - NEXT_PUBLIC_SUPABASE_URL
  - SUPABASE_SERVICE_ROLE_KEY
  - NODE_ENV='development'

Dependencias:
  - @supabase/supabase-js
  - next/cache (revalidatePath)

Estado:
  ✅ IMPLEMENTADA y lista para uso

9. TROUBLESHOOTING
================================================================================

PROBLEMA: Botón de eliminación no aparece
------------------------------------------
Causa posible 1: No estás en development
  Solución: Verifica que NODE_ENV='development'
  Comando: echo $NODE_ENV

Causa posible 2: No estás autenticado
  Solución: Inicia sesión primero

Causa posible 3: Error en renderizado
  Solución: Revisa consola del navegador

---

PROBLEMA: Error "This action is disabled in production"
--------------------------------------------------------
Causa: Intentaste ejecutar en producción
  Solución: Cambia a development:
  NODE_ENV=development npm run dev

---

PROBLEMA: Error "Supabase URL or Service Role Key not defined"
---------------------------------------------------------------
Causa: Variables de entorno faltantes
  Solución:
  1. Verifica que existe .env.local
  2. Verifica que contiene:
     NEXT_PUBLIC_SUPABASE_URL=...
     SUPABASE_SERVICE_ROLE_KEY=...
  3. Reinicia el servidor dev

---

PROBLEMA: Botón queda en "Eliminando..." indefinidamente
---------------------------------------------------------
Causa posible 1: Error de red
  Solución: Revisa consola del navegador

Causa posible 2: Permissions en Supabase
  Solución: Verifica que SERVICE_ROLE_KEY es correcto

Causa posible 3: Usuario ya fue eliminado
  Solución: Refresca la página

---

PROBLEMA: Usuario eliminado pero sigue apareciendo
---------------------------------------------------
Causa: Cache del navegador o de Next.js
  Solución:
  1. Hard refresh (Ctrl+Shift+R)
  2. O reinicia el servidor dev

---

PROBLEMA: No puedo registrar email después de borrar
-----------------------------------------------------
Causa posible 1: Cache de Supabase
  Solución: Espera 1 minuto y reintenta

Causa posible 2: Usuario no fue eliminado completamente
  Solución:
  1. Ve a Supabase Dashboard
  2. Authentication → Users
  3. Elimina manualmente si sigue ahí

---

PROBLEMA: Error en migración SQL
---------------------------------
Causa: Tablas ya fueron eliminadas
  Solución: Esto es normal, la migración es idempotente
  No requiere acción

---

PROBLEMA: Prisma schema desincronizado
---------------------------------------
Solución:
  npx prisma db pull
  npx prisma generate

---

PROBLEMA: TypeScript errors después de cambios
-----------------------------------------------
Solución:
  1. Elimina .next folder:
     rm -rf .next
  
  2. Reinstala dependencias:
     npm install
  
  3. Rebuild:
     npm run build
